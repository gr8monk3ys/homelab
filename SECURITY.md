# Security Policy

## Scope

This is a self-hosted homelab intended to run on a private network. It is not a
packaged product with released versions, so there is no supported-version
matrix — the `main` branch is the only supported state. Before exposing any
service publicly, review `docs/runbooks/hardening.md` and note the caveats in
the README: Pod Security Admission ships in `audit` mode and Kyverno is disabled
by default, so admission-time enforcement is opt-in.

## Reporting a Vulnerability

Please report suspected vulnerabilities privately via GitHub Security
Advisories:

- https://github.com/gr8monk3ys/homelab/security/advisories/new

Include the affected manifest/script, the impact, and reproduction steps where
possible. Because this is a personal project, expect a best-effort response
rather than a guaranteed SLA. Do not open public issues for security reports.

## Secret Handling

- No plaintext secrets are committed. Runtime credentials are generated by
  `scripts/generate-secrets.sh` (`openssl rand`) or stored SOPS/age-encrypted
  under `kubernetes/secrets/sops/` (only the **public** age recipient is in-repo).
- Never commit an `age` private key, kubeconfig, or `.env`. The pre-commit hook
  `.claude/hooks/block-sensitive-files.sh` and `.gitignore` guard against this,
  but treat them as backstops, not guarantees.
